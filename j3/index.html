Repository as world

Stop asking a model to type patches from scratch.

j3 starts with a constrained action space. The model ranks edit types, targets, and parameters; a deterministic patch engine turns that decision into a real diff.

  • State The current codebase, encoded from Python files and repo structure.
  • Action A structured patch such as changing an operator, literal, return value, import, or guard.
  • Observation Pytest output, assertion deltas, stack traces, type errors, and runtime behavior.
  • Target A passing test, cleaner trace, or executable goal that says what better means.

First demo

GreenShot is intentionally narrow.

Give j3 a Python repo and one failing pytest target. It predicts a structured repair, materializes a patch, and runs the target test in a temporary copy before touching your files.

greenshot-1 
$ python -m venv .venv
$ source .venv/bin/activate
$ python -m pip install -e ".[dev]"

$ j3 train --data examples/greenshot_bug

  --dry-run

How it works

A local loop with visible failure modes.

The early prototype keeps the action space small on purpose. It should learn useful edits from repo signals, or fail in a way that diagnostics can explain.

1

Mine and synthesize transitions

j3 generates synthetic break/fix records and can mine real Python before/after pairs from public git history.

2

Rank structured candidates

AST embeddings, action-delta prototypes, and failure hints put promising patches before wasted test runs.

3

Validate before apply

Patch and fix commands run candidates in isolated copies, print diffs, and keep the human in the loop.

Current result

Failure hints turned search into first-shot repairs on GreenShot-2.

GreenShot-2 is still small and shaped around bugs the current action space understands. That is the point: it proves the loop, not broad coding-agent capability.

Roadmap

Expand the benchmark before chasing a bigger neural model.

The next gate is practical: find repeatable ranking failures, missing actions, and weak context before moving toward a trainable candidate ranker.

Next

GreenShot-3 benchmark tasks

Add swapped call arguments, missing imports, wrong attributes, and narrow exception handling.

Then

Richer candidate generation

Implement action materializers and failure hints for import, attribute, call-shape, and exception errors.

Later

Candidate ranker from diagnostics

Train only after a larger ladder shows good candidates exist but sit behind bad candidates.

Pure mode claim

LLMs are optional for language. They are not the patch engine.

Use an executable signal, keep the repair loop local, and make every applied diff earn its test result.
