Reserve quota

src/quota.ptn · function excerpt

pub fn reserve(
    available: I64,
    amount: I64
) -> Result<I64, ReserveError> {
    if (amount <= 0) {
        return Result::Err(
            ReserveError::InvalidAmount
        );
    }
    if (amount > available) {
        return Result::Err(
            ReserveError::InsufficientQuota
        );
    }
    return Result::Ok(available - amount);
}

Check before subtracting.

The repair rejects invalid amounts and insufficient quota. A valid reservation still has to succeed: returning an error for every request would also violate the pact.

Write the rule at a boundary that matters.

A useful pact describes acceptable results independently of the algorithm. For quotas, worker allocation, or validation, a few stable properties can constrain many implementations. The pact itself still needs human review.

Beyond a function contract

Keep the agreement
through the whole change.

The executable quota workflow connects inspection, verification, protected edits, sandboxed execution, and replay.

01

Requirements survive edits.

An external baseline protects pacts and their meaning-defining helpers. Both text edits and semantic requests face the acceptance gate. Changing a requirement needs approval tied to the exact diff.

Protected changes ↗
02

Changes name their target.

Inspect signatures, callers, effects, and affected pacts through the semantic API. Stage an edit against persistent symbol IDs and a workspace revision. Managed snapshots commit atomically; stale proposals are rejected.

Semantic CLI ↗
03

Authority comes from the host.

Effect declarations expose requested operations. Host-issued, noncopyable handles grant tenant-scoped access. The Wasm host bounds memory and execution; the quota adapter enforces transactions, budgets, and cleanup.

Host boundaries ↗
04

Evidence follows the artifact.

Proofs, runtime guards, and executed tests have separate results bound to source, tools, policy, and artifact hashes. Quota traces replay against their recorded revision with zero live writes. Unknown and unsupported remain explicit.

Implementation status ↗

Know the current limits

Static proof covers a loop-free pure fragment; loops and recursion remain unsupported by the verifier. Invocation arguments are specialized into each Wasm artifact. Storage is in-memory. A complete LSP extension and external CI activation remain open.

Agent productivity gains have not been measured. This is an experimental developer preview.
